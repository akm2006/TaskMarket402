# 2. MetaMask Smart Accounts / Advanced Permissions

Normally, wallets work like this:

```
Dapp asks for transaction
User approves
Transaction happens
```

This is bad for AI agents because the user would need to approve every tiny action.

MetaMask Smart Accounts / Advanced Permissions allow this instead:

```
User gives limited permission once:
“Spend up to 3 USDC for this mission, valid for 24 hours.”
```

Then the app/agent can act **inside that limit**.

MetaMask describes Advanced Permissions as fine-grained permissions that let a dapp execute transactions on a MetaMask user’s behalf, for example spending a limited amount of USDC per day. [MetaMask](https://docs.metamask.io/smart-accounts-kit/concepts/advanced-permissions/?utm_source=chatgpt.com)

For our project, MetaMask is the **root authority**.

The user approves:

```
Mission: Analyze this token/wallet
Budget: 3 USDC
Duration: 24 hours
Max sub-agent spend: 0.50 USDC
Allowed use: x402 task payments only
```

So the agent does not get unlimited wallet control.

# 3. ERC-7715, ERC-7710, and EIP-7702 in simple words

You do not need to deeply master these immediately, but you should understand their role.

## ERC-7715

This is about **requesting permissions** from the user.

Example:

```
Can this app spend up to 3 USDC for this mission?
```

So ERC-7715 is like:

> “Ask the wallet for a scoped permission.”

## ERC-7710

This is about **using/redeeming that permission** to execute something.

Example:

```
Use part of the approved 3 USDC budget to pay Contract Scanner Agent 0.40 USDC.
```

So ERC-7710 is like:

> “Spend using the permission.”

## EIP-7702

This helps normal externally owned accounts behave more like smart accounts for delegated execution.

For our project, you can think:

> EIP-7702 helps the user’s wallet participate in smart-account-style delegated execution.

1Shot’s docs are specifically about gas abstraction for EIP-7710 delegated transactions and mention capability discovery, fee quotes, delegation payloads, and status tracking. [1Shot API](https://www.1shotapi.com/docs/quickstarts/gas-sponsorship-eip7710?utm_source=chatgpt.com)

# 4. What is x402?

x402 is the payment layer.

It revives the HTTP status code:

```
402 Payment Required
```

Basic x402 flow:

```
1. Client requests a paid API/resource.
2. Server replies: 402 Payment Required.
3. Client prepares payment.
4. Server verifies/settles payment.
5. Server returns the paid resource.
```

The x402 docs describe exactly this flow: a buyer requests a resource, the server returns `402 Payment Required` with payment instructions, the buyer submits a payment payload, and the server verifies/settles before returning the resource. [x402](https://docs.x402.org/introduction?utm_source=chatgpt.com)

Coinbase’s x402 docs explain it as an open payment protocol for instant automatic stablecoin payments over HTTP, useful for APIs and digital content. [Coinbase Developer Docs](https://docs.cdp.coinbase.com/x402/welcome?utm_source=chatgpt.com)

In our project, every specialist agent is a paid API:

```
Contract Scanner Agent → costs 0.40 USDC
Wallet Behavior Agent → costs 0.35 USDC
Market Context Agent → costs 0.25 USDC
```

When the Manager Agent calls the Contract Scanner:

```
Manager: Give me contract risk data.
Contract Scanner: 402 Payment Required, pay 0.40 USDC.
Manager: Pays via x402.
Contract Scanner: Returns analysis.
```

This is how agents get paid.

# 5. What is 1Shot?

1Shot is the relayer / gas abstraction layer.

Normally, even if you have permission, sending transactions can require gas, signing complexity, and chain-specific details.

1Shot helps send delegated transactions through a relayer.

For our project, 1Shot should be visible in the WorkGraph:

```
Payment: 0.40 USDC
Protocol: x402
Execution: ERC-7710
Relayer: 1Shot
Status: confirmed
```

The hackathon page describes 1Shot’s Permissionless Relayer as gas abstraction for EIP-7710 smart accounts, directly integrable over JSON-RPC. [HackQuest](https://www.hackquest.io/hackathons/MetaMask-Smart-Accounts-Kit-x-1Shot-API-x-Venice-AI-Dev-Cook-Off?utm_source=chatgpt.com)

So 1Shot is not the product. It is the execution rail.

# 2. MCPs we should use

| --- | --- |

| **Next.js DevTools MCP** | Lets the agent inspect Next.js app structure, logs, and docs |
| **Supabase MCP** | Helps manage database schema and inspect tables |
| **GitHub MCP** | Useful later for issues, PRs, repo management |
| **Browser/Fetch MCP** | Optional, for reading sponsor docs if Context7 does not cover them |

Context7 is specifically designed to give coding agents version-specific, up-to-date documentation instead of stale hallucinated APIs. [Upstash: Serverless Data Platform](https://upstash.com/blog/context7-llmtxt-cursor?utm_source=chatgpt.com) Playwright MCP gives agents browser automation through structured accessibility snapshots, useful for testing the WorkGraph UI without relying on screenshots. [Playwright](https://playwright.dev/docs/getting-started-mcp?utm_source=chatgpt.com) Supabase’s official MCP server provides development tools for querying and managing Supabase projects. [Supabase](https://supabase.com/docs/guides/ai-tools/mcp?utm_source=chatgpt.com) Next.js has official MCP guidance for coding agents and Next.js 16+ devtools support through `next-devtools-mcp`.
